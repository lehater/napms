# NAPMS documentation

The working documentation tree contains current project truth only. Git history is the archive.

- `requirements/` — accepted product and quality behavior.
- `domain/` — Strategic/Tactical DDD and semantic ownership.
- `architecture/` — accepted target architecture and structural constraints.
- `decisions/` — still-binding decisions not fully absorbed by a canonical owner.
- `engineering/` — current operational/implementation contracts.
- `ui/` — current reusable UI guidance.
- `plans/active/` — selected execution state.
- `process/` — reusable development and agent protocols.

The selected implementation MVP is `requirements/first-mvp-required-access-matrix.md`. Its execution state is `plans/active/README.md`.

Do not add archive, baseline, completed-audit, superseded-specification or migration-history documents to the working tree. Preserve that information in Git history instead.
